# 260726-th8: Anyone can complete task

## Objective

Add an optional per-task boolean `anyone_can_complete` (default `false`). When enabled, **any**
household member may check the task off / uncheck it — not just the assignee. When disabled
(the default), behaviour is byte-for-byte identical to today.

## Design contract (source of truth)

Model the field exactly like the existing `allow_exceed_target` flag. `allow_exceed_target` is the
checklist for every touchpoint: migration → `TaskRow`/`TaskRowWithCategory` → `shared::Task` →
`CreateTaskRequest`/`UpdateTaskRequest` → service create/update/read SQL → task modal → i18n →
test schema + test builder.

Two enforcement points:

1. **Backend** `backend/src/services/tasks.rs::complete_task` (and `uncomplete_task`, which has the
   same guard): the `NotAssigned` guard must also pass when `task.anyone_can_complete` is true.
2. **Shared UI logic** `shared/src/types.rs::TaskWithStatus::can_complete()`:
   `(self.is_user_assigned || self.task.anyone_can_complete) && (allow_exceed_target || !is_target_met())`.
   `is_user_assigned` keeps its literal meaning ("this user is the assignee") — do **not** force it true.

Points go to whoever checks the task off (existing behaviour, no change).

Open question to answer during execution: does the per-period completion counting in `tasks.rs`
(`if task.assigned_user_id.is_some()` at ~752 / ~788) count only the assignee's completions? If so,
an `anyone_can_complete` task must count **all** members' completions toward `target_count`.

## Tasks

### Task 1 — Thread the field through backend + shared types

Files:

- `backend/migrations/20240148000000_task_anyone_can_complete.sql` (new)
  `ALTER TABLE tasks ADD COLUMN anyone_can_complete BOOLEAN NOT NULL DEFAULT 0;`
- `shared/src/types.rs`: `Task.anyone_can_complete: bool`,
  `CreateTaskRequest.anyone_can_complete: Option<bool>`,
  `UpdateTaskRequest.anyone_can_complete: Option<bool>`.
- `backend/src/models/task.rs`: `TaskRow` + `TaskRowWithCategory` field + `to_shared()` mapping.
- `backend/src/services/tasks.rs`: INSERT/UPDATE column + bind, `create_task` default `false`,
  `update_task` patch, `list_pending_reviews` projection (`t_anyone_can_complete`).
- `backend/src/handlers/tasks.rs`: add to the Solo-Mode "no other changes" guard.
- `backend/src/test_utils.rs`: column in `create_test_schema()`, builder field,
  `with_anyone_can_complete(bool)`, INSERT bind, returned `Task`.
- `backend/src/services/tasks.rs` + `background_jobs.rs` inline test schemas: add the column.
- Mechanically extend every `Task` / `TaskRow` / `CreateTaskRequest` / `UpdateTaskRequest` struct
  literal in the workspace (backend, shared, frontend) with the new field.

Done when: `cargo check --workspace` is clean.

### Task 2 — Enforcement + counting semantics + tests

Files: `backend/src/services/tasks.rs`, `shared/src/types.rs`

- `complete_task` / `uncomplete_task`: `NotAssigned` guard skipped when `anyone_can_complete`.
- DRY: extract `count_completions` / `count_completions_in_period` helpers taking an
  `Option<&Uuid>` user filter; pass `None` when `anyone_can_complete` so all members' completions
  count toward `target_count` (both the `AlreadyCompleted` guard and period finalization).
- `shared`: add `TaskWithStatus::is_completable_by_user()` = `is_user_assigned || anyone_can_complete`
  and use it in `can_complete()` (expression identical to the design contract, extracted once so the
  frontend can reuse it).

Tests (backend, `#[tokio::test]`):
1. flag ON + assigned to someone else → non-assignee completion succeeds
2. flag OFF (default) + assigned to someone else → `TaskError::NotAssigned`
3. flag ON → non-assignee can `uncomplete_task`; flag OFF → `NotAssigned`
4. `create_task` without the field → `anyone_can_complete == false` (default preserved)
5. `update_task` toggles the flag and it round-trips through `get_task`
6. flag ON + `target_count = 2`: completions by two different members finalize the period

Tests (shared, `#[test]`): `can_complete()` true for non-assignee when flag ON, false when OFF,
and still false when target met with `allow_exceed_target = false`.

Done when: `cargo test --workspace` passes.

### Task 3 — Frontend toggle + i18n

Files: `frontend/src/components/task_fields.rs`, `frontend/src/components/task_modal.rs`,
`frontend/src/components/task_card.rs`, `frontend/src/translations/{de,en}.json`

- New `TaskAnyoneCanCompleteField` component (mirrors `TaskAllowExceedField`; same
  `form-group`/`form-hint` markup, no new CSS needed → mobile-first N/A).
- Task modal: signal `anyone_can_complete`, rendered directly below the `allow_exceed_target`
  control, sent in `CreateTaskRequest`/`UpdateTaskRequest`, plus a bulk-edit `BulkEditField`
  with its own `apply_anyone_can_complete` flag.
- `task_card.rs`: the `+/-` buttons are gated on `is_user_assigned` alone, so they must use
  `is_completable_by_user()` — otherwise the flag has no visible effect.
- i18n keys `task_modal.anyone_can_complete` / `.anyone_can_complete_hint` in de + en.
- Frontend test: `can_complete()` for a non-assignee with the flag on.

Done when: `cargo test --workspace` and `cargo clippy --workspace` are clean.
