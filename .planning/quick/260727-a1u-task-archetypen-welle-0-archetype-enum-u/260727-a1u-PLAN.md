# 260727-a1u: Task-Archetypen — Welle 0

## Objective

Welle 0 eines mehrstufigen UX-Umbaus. Ein `Task` ist heute polymorph: dieselbe Struct bedeutet je
nach vier Schaltern etwas völlig anderes (einmalige Aufgabe, Routine, gemeinsame Aufgabe, schlechte
Angewohnheit, Instandhaltung). Diese Welle schafft die **gemeinsame Ableitung**, auf der spätere
Wellen (Formular, Karte) aufsetzen.

**Scope:** ausschließlich `shared/src/types.rs`, **rein additiv**.
Kein Backend, kein Frontend, keine Migration, keine API-Änderung.

## Design contract (source of truth)

### 1. `Archetype`

```rust
pub enum Archetype {
    OneOff,
    Routine,
    Shared,
    BadHabit,
    Maintenance,
}
```

Ableitungen: `#[derive(Debug, Clone, Copy, PartialEq, Eq, Serialize, Deserialize)]` mit
`#[serde(rename_all = "snake_case")]`.

> `snake_case` (nicht `lowercase` wie bei `HabitType`/`RecurrenceType`), weil zwei Varianten
> mehrteilig sind — `ConditionType` im selben File ist das Vorbild für mehrteilige Varianten.
> `Serialize`/`Deserialize` dient **nur** der Konsistenz mit dem restlichen File; `Archetype` wird
> nirgends übertragen, es ist eine reine Ableitung.

### 2. Ableitung — Prioritätsreihenfolge (bewusste Design-Entscheidung)

`Task::archetype(&self) -> Archetype`, exakt diese Reihenfolge, erster Treffer gewinnt:

| # | Bedingung | Ergebnis |
| - | --------- | -------- |
| 1 | `assignee_cannot_uncomplete == true` | `Maintenance` (**unabhängig vom `habit_type`**) |
| 2 | `habit_type.is_inverted()` | `BadHabit` |
| 3 | `anyone_can_complete == true` | `Shared` |
| 4 | `recurrence_type == RecurrenceType::OneTime` | `OneOff` |
| 5 | sonst | `Routine` |

Mehrdeutige Kombinationen sind möglich und erlaubt (z. B. `Bad` + `anyone_can_complete`). Die
Reihenfolge sortiert nach *auffälligster, bedienungsprägendster* Eigenschaft: wer die Aufgabe nicht
selbst wieder abhaken darf, erlebt zuerst genau das; eine schlechte Angewohnheit prägt die Bedienung
stärker als "wer darf abhaken"; und "wer darf abhaken" wiederum stärker als der Rhythmus.

**Grundsatz (muss ins Doc-Comment von `archetype()`):** Der Archetyp bestimmt ausschließlich die
*Darstellung*. Was jemand tatsächlich darf, kommt weiterhin aus `can_complete()` /
`can_uncomplete()`. Eine ungewöhnliche Flag-Kombination darf höchstens ein suboptimales Etikett
ergeben, aber **nie** das Verhalten ändern.

### 3. `ArchetypeDefaults` + `Archetype::defaults()`

```rust
pub struct ArchetypeDefaults {
    pub habit_type: HabitType,
    pub anyone_can_complete: bool,
    pub assignee_cannot_uncomplete: bool,
    /// `Some(OneTime)` nur für `OneOff`; `None` heißt "der Nutzer wählt den Rhythmus".
    pub recurrence_type: Option<RecurrenceType>,
}
```

Ableitungen: `#[derive(Debug, Clone, PartialEq, Eq, Serialize, Deserialize)]` — **kein `Copy`**,
`RecurrenceType` ist nicht `Copy`.

Presets (so gewählt, dass der Round-Trip aus Test 3 aufgeht):

| Archetype     | habit_type | anyone_can_complete | assignee_cannot_uncomplete | recurrence_type   |
| ------------- | ---------- | ------------------- | -------------------------- | ----------------- |
| `OneOff`      | `Good`     | `false`             | `false`                    | `Some(OneTime)`   |
| `Routine`     | `Good`     | `false`             | `false`                    | `None`            |
| `Shared`      | `Good`     | `true`              | `false`                    | `None`            |
| `BadHabit`    | `Bad`      | `false`             | `false`                    | `None`            |
| `Maintenance` | `Good`     | `false`             | `true`                     | `None`            |

> `Maintenance` setzt `anyone_can_complete` bewusst **nicht** mit: `Task::is_household_wide()`
> liefert bereits allein aus `assignee_cannot_uncomplete` `true` — beide Flags wären redundant.

### 4. `Archetype::assignment_required(&self) -> bool`

`true` nur für `Maintenance`, sonst `false`.

Begründung ins Doc-Comment: `TaskWithStatus::is_assignee()` verlangt `assigned_user_id.is_some()`;
ohne zugewiesene Person greift die `can_uncomplete()`-Sperre nie — eine Instandhaltung ohne
Zuweisung wäre also stillschweigend wirkungslos.

### 5. Was unangetastet bleibt

Keine bestehenden Felder, Methoden oder Signaturen ändern. Insbesondere `can_complete()`,
`can_uncomplete()`, `is_assignee()`, `is_completable_by_user()` und `is_household_wide()` bleiben
Zeile für Zeile wie sie sind.

### 6. Platzierung im File

- `Task::archetype()` → **in den bestehenden `impl Task`-Block** (aktuell Zeile 648–657), direkt
  neben `is_household_wide()`.
- `pub enum Archetype`, `pub struct ArchetypeDefaults`, `impl Archetype` → **nach** dem
  `impl Task`-Block, **vor** `pub struct CreateTaskRequest` (aktuell Zeile 659). Alles bleibt so im
  Abschnitt `// Task Types`.
