<objective>
Build the delivery core: one target abstraction, one transport seam, one error taxonomy, one OOC
wrapper — plus the report shortener that keeps a long day from failing the send.

Purpose: this is where the entire behavioural risk of the phase lives, and almost all of it is pure
functions. Putting them behind a one-method transport trait makes them testable without a network and
is the only way to assert D-10 (raw `Authorization` header) at all. The shortener lives next to the
report formatter it has to agree with, not in the sender.

Output: `services/nomi.rs` with the pure core plus the reqwest implementation, and
`generate_daily_report_capped` in `services/report.rs`.
</objective>

<assumptions>
- **A-09 (C-2, closed by the briefing):** both length-error spellings are handled —
  `MessageCharacterLimitExceeded` (rooms) and `MessageLengthLimitExceeded` (direct). A `match` on one
  spelling falls through silently for the other endpoint.
- **A-10 (C-3, closed by the briefing):** the official docs document no `Retry-After` header. It is
  parsed opportunistically when present and ignored when absent; the backoff policy is ours. NOMI-05's
  literal wording ("honour `Retry-After`") therefore cannot be met as stated — it is met as
  "recognise 429 and back off, using `Retry-After` when the server volunteers it".
- **A-11 (C-1, decided ENGLISH):** the truncation counter reads `… and N more`. `report.rs:1-5`
  makes the whole report text English by design because a later phase feeds it to an LLM; the counter
  is part of that text. Only the settings UI is localized (plan 05-05).
- **A-12 (shortening order, RESEARCH degenerate case 2):** "Due today" gives way first;
  "Missed yesterday" is touched only if the message still does not fit, because D-16 says truncating
  from the end would drop the more interesting half. Each shortened section keeps at least one line
  plus the counter until nothing else can be removed.
- **A-13 (degenerate case 1):** when the header alone busts the budget, the household name is
  truncated with a trailing `…` rather than looping or panicking. Below the fixed skeleton cost
  (~90 characters, which nothing in D-16's strategy can remove) the function falls back to a
  documented hard clamp. It therefore always returns a string within the limit, for every argument.
  Production never reaches the clamp: the runtime limit is clamped up to `MIN_MESSAGE_LIMIT = 120`
  in `NomiJobSettings::from_config`.
- **A-14 (D-06 / NOMI-06):** `deliver` receives finished `message_text`. The OOC wrapping and the
  shortening happen in the caller. A second content type later needs a new producer and zero edits here.
</assumptions>
