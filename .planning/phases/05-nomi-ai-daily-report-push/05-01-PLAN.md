<assumptions>
Recorded explicitly, per CLAUDE.md § Design-Driven Implementation. None of these reopens a locked
decision; each closes a gap RESEARCH.md left open.

- **A-01 (D-17, message limit):** the nomi character limit is a runtime value carried by
  `Config.nomi_message_limit` (env `NOMI_MESSAGE_LIMIT`, default 800), not a `const` consulted at
  the call site. Changing it needs an env var change, not a recompile.
- **A-02 (Pitfall 8):** `NOMI_ENCRYPTION_KEY` is optional. Absent or malformed means the nomi.ai
  integration is off — endpoints answer 503, the job skips its pass. It never panics `from_env()`.
- **A-03:** `Config` gains a hand-written `Debug` impl. `jwt_secret` was already exposed via the
  derived `Debug`; this plan fixes that at the same time rather than adding a second secret to it.
- **A-04 (schema drift guard):** the guard test executes the new migration file via `include_str!`
  into a fresh pool rather than running all 50 migrations. Cheaper, deterministic, and it tests
  exactly the thing that drifts. If `sqlx::raw_sql` proves unavailable, split the file on `;` and
  execute the statements in order — do not weaken the comparison.
</assumptions>

<assumption_delta>
**Identity/credential model: `add-alongside`.**

Every credential in this codebase so far is inbound and hashed — argon2 passwords and sha2 refresh
tokens in `services/auth.rs`, compared and thrown away. This phase adds the first *outbound*
credential, which must be recoverable to be used, so it is encrypted at rest in a separate module
(`services/crypto.rs`) that shares no code, no table and no error type with `services/auth.rs`.
Nothing about the inbound model changes.

What would later force a promote to a shared credential abstraction: a second outbound integration
needing the same store/decrypt/rotate lifecycle, or a requirement to rotate `NOMI_ENCRYPTION_KEY`
without every member re-entering their key. At that point the `[version]` byte reserved in the
stored blob layout becomes the migration path and a generic `encrypted_secrets` table is justified.
Until then a second abstraction layer would be speculative.
</assumption_delta>

<threat_model>
This phase handles a third-party credential in **recoverable** form. Threats are rated for this
plan; `high` threats each name the task that mitigates them.

| ID   | Threat | Rating | Mitigating task |
|------|--------|--------|-----------------|
| T-01 | **Nonce reuse under one AES-GCM key** — re-encrypting on update with the stored nonce leaks the XOR of both plaintexts and enables tag forgery. | high | Task 2 — `seal` generates its own nonce from `OsRng` internally and exposes **no** nonce parameter; `nonce_is_fresh_per_call` proves it |
| T-02 | **Key material in `Debug` output** — `Config` derives `Debug`, is cloned into `AppState` and into `web::Data`; a single `{:?}` in a handler or a panic message ships both secrets to the journal. | high | Task 1 — hand-written `Debug` printing `<redacted>` / `<set>`; `test_debug_redacts_secrets` asserts it. Task 4 — the same for `NomiJobSettings` |
| T-03 | **The stored column holds the plaintext key** — a mistake here is invisible until someone reads the DB file. | high | Task 2 — `sealed_bytes_do_not_contain_plaintext`; Task 3 stores the sealed blob in a `BLOB` column named `api_key_encrypted`, never a `TEXT api_key` |
| T-04 | **A malformed or rotated key panics the whole household app** — availability loss for every user, not just nomi users. | high | Task 1 (`Option<String>`, never `.expect`) + Task 2 (`decode_key_from_config` logs and returns `None`) + Task 4 (`is_enabled()` false ⇒ the job skips) |
| T-05 | Key length confusion — a 24- or 48-byte base64 value silently accepted and truncated. | medium | Task 2 — `decode_key` returns `BadKeyLength` for anything but exactly 32 bytes; tests cover 31 and 33 |
| T-06 | Test schema drift hides a wrong column type or a missing NOT NULL until production. | medium | Task 3 — the PRAGMA-tuple drift guard |
| T-07 | The encryption key auto-generated into `${stateDir}` is only as safe as the state dir. | low | Accepted: `DATABASE_URL` already lives in the same directory, so losing it already loses the data. Documented in plan 05-04 (module.nix). |
