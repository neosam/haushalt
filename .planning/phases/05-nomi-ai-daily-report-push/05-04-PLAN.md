configure their connection over HTTP.

at the right local moment, keeps one member's broken key from costing everyone else their report,
and gives the deployment a way to supply the encryption secret alongside the existing JWT secret.

Output: `process_nomi_sends` in the background loop, three routes under
`/api/households/{household_id}/nomi`, and the `module.nix` options.

<assumptions>
- **A-15 (retry shape, explicitly Claude's discretion):** at most **two** delivery attempts per
  connection per local day. A `Transient` or `RateLimited` first failure is retried once after
  `min(retry_after.unwrap_or(5), 15)` seconds inside the same tick; a `TooLong` failure is retried
  once immediately with the report regenerated at a 400-character budget (which covers both a lowered
  server-side limit and a free account, per D-17). Everything else is not retried. Then the day is
  latched regardless of outcome.
- **A-16 (Pitfall 4):** `last_attempt_date` is written on **every** attempt, success or failure. One
  attempt per local day. The cost — a transient failure loses that day's report — is accepted; the
  alternative retries every 60 seconds against a rate limit whose documented penalty is losing API
  access.
- **A-17 (target-selection ordering, RESEARCH § The target-selection ordering problem):** two-step.
  The key is saved first, and `GET …/nomi/targets` then uses the **stored** key. The plaintext key
  therefore travels exactly one request path, not two (D-22).
- **A-18:** when `NOMI_ENCRYPTION_KEY` is absent, all three routes answer `503` with
  `error: "nomi_disabled"`, and the background pass is skipped with no log noise beyond the single
  startup line from plan 05-01.
- **A-19 (module.nix):** the encryption key may be auto-generated into `${stateDir}` because
  `DATABASE_URL` already points into the same directory — losing it already loses the data, so the key
  is no more fragile than the database it protects. This argument must appear in the option
  description, otherwise the auto-generation looks careless.
</assumptions>
