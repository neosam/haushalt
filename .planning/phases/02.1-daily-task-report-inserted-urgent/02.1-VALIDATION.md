# Phase 2.1 — Validation Strategy

> Per-phase validation contract for feedback sampling during execution.
> Derived from `02.1-RESEARCH.md` § Validation Architecture.

---

## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | Rust built-in `cargo test` harness (`#[test]` / `#[tokio::test]`), inline `#[cfg(test)] mod tests` — no separate test framework or config file in the repo |
| **Config file** | none — test behavior is governed only by `Cargo.toml` `[lints] workspace = true` |
| **Quick run command** | `nix develop -c cargo test -p backend report::` |
| **Full suite command** | `nix develop -c cargo test --workspace` |
| **Estimated runtime** | quick ~10–30 s (module filter), full suite several minutes (cold builds are slow) |

**Toolchain note:** `cargo`, `node` and `gsd-tools` are not on the bare PATH. Every
command must be prefixed with `nix develop -c`. Plain `nix develop` works — the
`NIXPKGS_ALLOW_UNFREE=1 --impure` note in older docs is obsolete since `2e42e4e`.

---

## Sampling Rate

- **After every task commit:** `nix develop -c cargo test -p backend report::`
- **After every plan wave:** `nix develop -c cargo test --workspace` **and**
  `nix develop -c cargo clippy --workspace`
- **Before `/gsd-verify-phase`:** Full suite green
- **Max feedback latency:** ~30 s for the per-task command

**Known out-of-scope failure:** `frontend/src/components/solo_mode_banner.rs:66` trips
`clippy::type_complexity` under the current toolchain and fails `-D warnings`. This is
pre-existing and **not** this phase's to fix. It must not be counted as a phase
regression, and it must not be "fixed" as a side effect.
