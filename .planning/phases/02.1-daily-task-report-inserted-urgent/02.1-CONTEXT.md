# Phase 2.1: Daily Task Report (INSERTED — urgent) - Context

**Gathered:** 2026-07-26
**Status:** Ready for planning

<domain>
## Phase Boundary

Per household, the logged-in user gets a report view showing which tasks are due
for them **today** and what went wrong **yesterday**. The report is rendered as a
single plain-text block, generated in the backend, always in English, with a
copy-to-clipboard button. Read-only — no completing, editing, or navigating to
tasks from the report.

Requirements: RPT-01, RPT-02, RPT-03, RPT-04.

**Explicitly out of scope:** date navigation, interactivity, LLM integration,
per-household-member reports, notification/scheduling of the report.

</domain>

<decisions>
## Implementation Decisions

### Purpose & Language (drives several decisions below)

- **D-01:** The report text is **generated in the backend** and is **always
  English**, regardless of the UI language. Reason stated by the user: in a later
  version the text will be sent to an LLM automatically. For now, the user only
  wants to copy it manually. Do **not** route the text through the frontend i18n
  system.
- **D-02:** Keep the text format stable and machine-parseable (fixed section
  headers, one task per line). It is a human-readable report today and an LLM
  prompt payload later.

### Data Source — "Due today"

- **D-03:** Compute live from the task list using
  `scheduler::is_task_due_on_date(task, today)`.
- **D-04:** "Today" is resolved in the **household timezone** (from
  `household_settings.timezone` via `scheduler::parse_timezone` /
  `scheduler::today_in_timezone`), **not** UTC.
- **D-05:** The existing `GET /households/{id}/tasks/due` endpoint
  (`tasks::get_due_tasks`) stays untouched — it uses `Utc::now().date_naive()`,
  which is a pre-existing inaccuracy. The report gets its own, correct
  computation in the new report service. (Fixing `get_due_tasks` is a deferred
  idea, see below.)
- **D-06:** Inverted habits (bad habits, `habit_type.is_inverted()`) are **not**
  listed in the "due today" section at all — "due" makes no sense for something
  you are supposed to avoid.
- **D-07:** Tasks already completed today **remain listed** in the "due today"
  section, marked as done. *(Claude's discretion on the exact marker — proposed:
  a `(done)` suffix on the line.)*

### Data Source — "Missed yesterday"

- **D-08:** Read from the **`missed_task_penalties` table** (`task_id`,
  `due_date = yesterday`), not from a live recomputation. Rationale: the report
  should show what the system actually penalized.
- **D-09:** Only entries for which a **penalty was actually applied** count as
  missed. For inverted habits the background job awards a *reward* for not doing
  them, so rows in `missed_task_penalties` belonging to inverted habits are
  **excluded**.
- **D-10:** **Additionally**, inverted habits that *were performed* yesterday are
  listed as missed — the user's rule is "everything that went wrong yesterday
  belongs in there". These do **not** appear in `missed_task_penalties`; they are
  `task_completions` rows with `due_date = yesterday` on a task whose
  `habit_type` is inverted.
- **D-11:** Both sources go into **one single section** ("Missed yesterday"),
  without separate sub-labels. *(User: "Lass es erst mal in einer.")*
- **D-12:** "Yesterday" is likewise resolved in the household timezone.

### Scope — "my tasks"

- **D-13:** A task counts as the user's own if `assigned_user_id == current_user`
  **or** the task has no assignee (unassigned tasks hit every household member in
  the background job, so they hit the user too).
- **D-14:** Exclusions mirror the background job: archived tasks, paused tasks,
  and pending suggestions are excluded everywhere. In the "missed yesterday"
  section, one-time tasks (`RecurrenceType::OneTime`) and household vacation days
  are additionally excluded.
- **D-15:** Note for the planner: `missed_task_penalties` has **no `user_id`**
  column. The per-user filter must be applied by joining to `tasks` and applying
  the D-13 rule. Do not add a column / migration for this phase.

### API

- **D-16:** **One** endpoint, `GET /households/{id}/report`, returning both
  sections in a single response.
- **D-17:** Response body carries **only the generated text**, e.g.
  `{ "report_text": "..." }`. No structured task lists. New shared type in
  `shared/src/types.rs`.
- **D-18:** Strictly today/yesterday — **no** `?date=` parameter.
- **D-19:** Report logic lives in a backend **service** (`backend/src/services/`)
  with unit tests, per RPT-04; the handler stays thin.

### Text Format

- **D-20:** Line format (not prose sentences), section headers followed by
  `- ` bullets:

  ```
  Daily report — Kitchen — Sat, 2026-07-26

  Due today:
  - Empty the dishwasher
  - Take out the trash
  - Clean the litter box (by 20:00)

  Missed yesterday:
  - Vacuuming
  ```

- **D-21:** Per task, show the **title plus the deadline time if `due_time` is
  set** — no points, no category.
- **D-22:** Section order: "Due today" first, "Missed yesterday" below.
- **D-23:** Empty states, English, per section:
  - Due today → `No tasks scheduled for today`
  - Missed yesterday → `All tasks completed yesterday`

  Both sections are always rendered, each with its own empty-state line — there
  is no combined "everything empty" variant.

### Frontend

- **D-24:** New household tab at `/households/:id/report`, label **"Bericht"**
  (de) / **"Report"** (en), positioned **directly after "Aufgaben"/Tasks** in the
  tab bar. Wire through `HouseholdTab` enum, `HouseholdLayout` active-tab
  detection, `app.rs` route, and the `tabs.*` i18n keys.
- **D-25:** **Read-only** view. No completing, no opening the task modal, no
  links to tasks.
- **D-26:** The page renders the backend text block verbatim (preformatted /
  whitespace-preserving) plus a **"Kopieren" / "Copy" button** above it that puts
  the text on the clipboard. No Web Share API.
- **D-27:** Tab label and copy button are translated (de/en) as usual — only the
  **report text itself** is English-only.

### Claude's Discretion

- Exact marker for tasks already completed today (D-07) — proposal: `(done)`
  suffix.
- Exact date/household-name header line wording and formatting.
- Sorting inside each section (proposal: by deadline time, then title —
  consistent with `get_all_tasks_with_status`).
- CSS/component choice for the preformatted text block and the copy button.

</decisions>

## Existing Code Insights

### Reusable Assets

- `backend/src/services/scheduler.rs` — `is_task_due_on_date`, `is_task_overdue`,
  `parse_timezone`, `today_in_timezone`, `parse_due_time`, `get_task_deadline_utc`.
  This is the exact logic the background job uses; the report service should reuse
  it rather than re-derive due-date rules.
- `backend/src/services/background_jobs.rs::process_missed_tasks` (lines ~184-368)
  — reference implementation for the miss semantics: household timezone,
  vacation skip, paused/archived/one-time skips, completion lookup by
  `(task_id, due_date)`, and the `missed_task_penalties` write. Read this before
  writing the report query.
- `backend/src/services/household_settings.rs` — `get_or_create_settings`,
  `is_household_on_vacation`.
- `backend/src/services/tasks.rs` — `list_tasks`, `get_due_tasks` (pattern to
  follow, but with the UTC bug avoided), `get_all_tasks_with_status` (sorting
  pattern).
- `backend/src/test_utils.rs` — shared in-memory DB, fixtures, builders,
  assertion helpers built in Phase 2 plan 02-01. Report service tests must use
  these.
- `frontend/src/components/household_tabs.rs` — `HouseholdTab` enum with
  `i18n_key()` / `path()`; add the new `Report` variant here.
- `frontend/src/components/household_layout.rs` — active-tab detection by path
  suffix; add a `path.ends_with("/report")` branch.

### Established Patterns

- Backend layering: `handlers/*.rs` (thin, `AuthenticatedUser` extractor) →
  `services/*.rs` (logic + inline `#[cfg(test)] mod tests`) → `models/*Row`.
- Shared API types live in `shared/src/types.rs` and are used identically on both
  sides.
- Tests live in `#[cfg(test)] mod tests` next to the code; in-memory SQLite per
  test; date/time passed **into** the function under test rather than mocked
  globally (v1.1 decision) — the report service should take the "today" date as a
  parameter so tests can pin it.
- SQLx offline mode: run `cargo sqlx prepare` after adding queries.
- Frontend pages call `ApiClient` methods in `frontend/src/api/mod.rs`.

### Integration Points

- New route registration in `backend/src/handlers/mod.rs` +
  `backend/src/services/mod.rs`.
- `frontend/src/app.rs` — add `<Route path="report" view=ReportPage />` inside the
  `HouseholdLayout` route block (after `tasks`).
- `frontend/src/pages/mod.rs` — register the new page module.
- `frontend/src/translations/de.json` / `en.json` — `tabs.report` and copy-button
  keys.
- Clipboard access from WASM goes through `web_sys` (navigator.clipboard).

### Known Landmines

- **Pre-existing clippy failure**, unrelated to this phase:
  `frontend/src/components/solo_mode_banner.rs:66` trips `clippy::type_complexity`
  under the current toolchain and fails `-D warnings`. Do not let this block
  verification of this phase; do not "fix" it as a side effect either.
- `nix develop` needs `NIXPKGS_ALLOW_UNFREE=1` and `--impure`; without it there is
  no `cargo`.
- `missed_task_penalties` rows only exist if the background job actually ran. On a
  freshly seeded dev/test DB the "missed yesterday" section will be empty even
  when tasks were objectively missed. Tests must insert the rows explicitly.

<specifics>
## Specific Ideas

- **Why English + backend generation:** the user plans to send this text to an LLM
  automatically in a later version. That is the reason the text does not go
  through frontend i18n and is not localized. Today the only consumer is a manual
  copy-paste.
- **Target text shape** (user-approved example):

  ```
  Daily report — Kitchen — Sat, 2026-07-26

  Due today:
  - Empty the dishwasher
  - Take out the trash
  - Clean the litter box (by 20:00)

  Missed yesterday:
  - Vacuuming
  ```

- **Empty-state wording** was chosen by the user verbatim:
  `No tasks scheduled for today` / `All tasks completed yesterday`.
- **User's framing of "missed":** "Alles was gestern schief lief soll da drin
  stehen" — i.e. missed good habits *and* performed bad habits, in one list.

</specifics>

<deferred>
## Deferred Ideas

- **Send the report to an LLM automatically** — the stated motivation behind D-01;
  its own future phase (scheduling, provider choice, prompt design, privacy).
- **Date navigation** (`?date=` parameter, browsing older reports) — deliberately
  out of scope (E2).
- **Structured report response** (task IDs / typed lists next to the text) —
  rejected for now (H3 a); revisit when the UI becomes interactive or the LLM
  integration needs structure.
- **Interactivity in the report** (complete a task, open the task modal, retro-fix
  a missed task) — rejected for now (D1 a).
- **"Avoided yesterday 🎉" section** for bad habits successfully not done — the
  positive counterpart; not wanted in this phase.
- **Web Share API / share button** next to copy — rejected (F3 a).
- **Fix `tasks::get_due_tasks` to use the household timezone** instead of UTC —
  a real pre-existing inaccuracy found while scouting, but a change to shipped
  v1.0 behavior with its own blast radius. Candidate for a `/gsd-quick` task or a
  later phase.

</deferred>
