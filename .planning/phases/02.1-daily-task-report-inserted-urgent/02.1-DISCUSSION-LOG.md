## A) Data source "missed yesterday"

### A1 — Where does "missed" come from?

| Option | Description | Selected |
|--------|-------------|----------|
| a) Compute live | Same logic as the background job (due yesterday + not completed), in a new report service — independent of whether the job ran (Claude's recommendation) | |

**User's choice:** b
**Notes:** The report should reflect what the system actually penalized.

### A2 — Inverted habits (bad habits)

| Option | Description | Selected |
|--------|-------------|----------|
| a) Exclude from "missed" | Not doing a bad habit is a success, not a miss (Claude's recommendation) | |
| b) Separate "avoided yesterday 🎉" section | Show them as a positive third section | |
| c) Include | Throw them into the missed list | ✓ (qualified) |

**User's choice:** c — "aber richtig machen, also mit reinnehmen, wenn Strafe vergeben wurde"
**Notes:** Clarified in round 3 (G1/H1): the rule is "everything that went wrong
yesterday". Bad habits that were *avoided* got a reward, not a penalty → excluded.
Bad habits that were *performed* are a failure → included, sourced from
`task_completions` rather than `missed_task_penalties`. Both kinds go into one
combined section (H1: "Lass es erst mal in einer").

### A3 — Timezone

**User's choice:** Household timezone, yes.
**Notes:** The second half of the question — whether to also fix the existing
`get_due_tasks` (UTC) — was not answered explicitly. Assumption recorded in
