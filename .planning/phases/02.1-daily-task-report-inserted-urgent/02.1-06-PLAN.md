**Endpoints used for seeding:**
- `POST /api/auth/register` body `{"username","email","password"}` (`shared::CreateUserRequest`)
  → `{"data":{"token","refresh_token","user":{...}}}`
- `POST /api/auth/login` body `{"username","password"}` (`shared::LoginRequest`)
- `POST /api/households` body `{"name"}` (`shared::CreateHouseholdRequest`) — the creator becomes Owner
- `POST /api/households/{id}/tasks` body `shared::CreateTaskRequest`: required
  `{"title","recurrence_type"}`; optional `description`, `recurrence_value`, `assigned_user_id`,
  `target_count`, `time_period`, `allow_exceed_target`, `requires_review`, `points_reward`,
  `points_penalty`, `due_time` (`"HH:MM"`), `habit_type` (`"good"` | `"bad"`), `category_id`.
  `recurrence_type` serialises lowercase: `"daily" | "weekly" | "monthly" | "weekdays" | "custom" | "onetime"`.
- `GET /api/households/{id}/report` → `{"data":{"report_text":"..."}}`
All authenticated calls need `Authorization: Bearer {token}`.

**Direct SQL is required for the backdated rows** — the API cannot create yesterday's state:
- `INSERT INTO missed_task_penalties (task_id, due_date) VALUES ('<task-uuid>', '<yesterday>');`
- `INSERT INTO task_completions (id, task_id, user_id, completed_at, due_date, status) VALUES (...,'approved');`
  for the indulged-bad-habit row, with `due_date` set to yesterday.

**Expected report shape (D-20, user-approved):** a header line
`Daily report — {household name} — {Ddd, YYYY-MM-DD}`, a blank line, `Due today:` followed by
`- ` bullets or `No tasks scheduled for today`, a blank line, `Missed yesterday:` followed by
`- ` bullets or `All tasks completed yesterday`.
